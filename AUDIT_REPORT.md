**Date:** 2026-06-03 (Updated)
**Auditor:** Senior Full-Stack Engineer

**Status:** PARTIALLY REFACTORED — Critical architectural fixes in progress; fantasy code still present in several modules

---

## Executive Summary

This codebase was generated by Replit AI Agent and originally contained significant amounts of fantasy/hallucinated code — modules that looked functional but could not actually produce real data. A fix guide was issued prescribing removal of LLM-based extraction, AI URL discovery, fake skip-trace scrapers, and replacement with real per-county Playwright scrapers.

**Current State:** The infrastructure layer (browser pools, circuit breakers, retry queues, proxy pools, Fargate deployment) has been well-implemented and is production-grade. However, **the data extraction layer still contains substantial fantasy code** that has not yet been refactored per the fix guide. The project has two parallel scraping architectures that are poorly integrated:

- **Path A (Authenticated):** Propelio, Propwire — Uses Playwright with session persistence, stealth, and proxy pinning. Partially functional but lacks CAPTCHA solving.
- **Path B (Generic):** 200+ county/government sources — Still uses Crawl4AI directly with no stealth, no session persistence, no form interaction, and **100% LLM-based extraction from stripped HTML text**. Still completely non-functional for interactive government portals.

**The result:** Jobs return "completed" with empty arrays, the frontend receives inconsistent JSON, and zero real distressed leads or cash buyers are actually extracted from county/government sources. Propelio/Propwire authenticated flows work when not blocked.

## 1. Fantasy / Hallucinated Code — Status of Removal

### 1.1 LLM-Based Data Extraction (workers/llm.py)
**File:** workers/llm.py
**Functions:** `parse_distressed_page()`, `extract_investor_profile()`, `score_buyer_match()`, `suggest_distressed_sources()`
**Severity:** CRITICAL
**Status:** ❌ **STILL PRESENT** — Not yet refactored

**What it does:**
- `parse_distressed_page()`: Takes raw text stripped from HTML via `BeautifulSoup(html, "lxml").get_text()`, sends up to 9,000 characters to OpenAI with a prompt asking for structured JSON, returns listings.
- `extract_investor_profile()`: Scrapes text → sends to LLM → returns investor profile JSON.
- `score_buyer_match()`: Sends buyer + lead to LLM for "match scoring".
- `suggest_distressed_sources()`: Asks LLM to discover source URLs for counties.

**Why it is fantasy:**
- Government/county sites do NOT put structured foreclosure data on their homepages as plain text.
- The LLM hallucinates listings when it cannot find real data.
- No validation that returned addresses exist in the original text.
- No schema enforcement — LLM returns arbitrary JSON shapes.
- Cost: Every scrape costs API credits. With 200+ sources, this is unsustainable.

**Required Action:** Remove all four functions. Keep `_chat()` helper ONLY for non-extraction tasks (e.g., classifying a buyer as "flipper" vs "landlord" AFTER data is already extracted). Replace with per-site DOM parsers in `workers/scrapers/counties/`.

### 1.3 Fake Skip-Trace Scrapers (workers/skip_trace.py / workers/osint_skip_trace.py)
**File:** workers/osint_skip_trace.py (imported in main.py), workers/skip_trace.py
**Severity:** CRITICAL
**Status:** ⚠️ **PARTIALLY ADDRESSED** — `osint_skip_trace.py` still used in foreclosure pipeline

**What it does:**
- `skip_trace.py`: Contains `trace()` function used by `/scrape/skip-trace` endpoint.
- `osint_skip_trace.py`: Used in foreclosure lead-gen pipeline for `trace_by_address()` and `format_markdown_table()`.

**Why the original was fantasy:**
- FastPeopleSearch, CyberBackgroundChecks, etc. aggressively block scrapers and sue for TOS violations.
- Google search scraping is instantly blocked after a few requests.
- Legal liability: scraping people-search sites violates FCRA/GLBA.

**Required Action:** Remove ALL people-search scrapers. Replace with licensed skip-trace API integration (BatchSkipTracing, TLO, LexisNexis) or document that skip-tracing requires paid API keys. See Fix Guide Phase 1.3.

### 1.6 Zillow Scraper
**File:** Inline in `workers/main.py` (endpoint `/zillow`) AND `workers/http_client.py` (Crawl4AI fallback)
**Severity:** HIGH
**Status:** ⚠️ **PARTIALLY ADDRESSED** — Playwright-based extraction exists but lacks DataDome challenge detection

**What it does:**
- Extracts `__NEXT_DATA__` from Zillow Next.js pages via Playwright.
- Checks if `next_data_raw` is empty.

**Why it is still problematic:**
- Zillow uses DataDome protection. Headless browsers from AWS Fargate IPs are instantly challenged.
- The check "if not next_data_raw" does not distinguish between a real page with no data vs a bot challenge page.
- No CAPTCHA solving for DataDome challenges.

**Required Action:** Add DataDome challenge detection and CAPTCHA solving. Mark as unreliable without residential proxies. See Fix Guide Phase 4.

## 2. Architecture Issues — Status of Fixes

### 2.1 Two Disconnected Scraping Paths
**Issue:** The repo has `browser_context()` (Path A) for authenticated scrapers and `fetch_html()` (Path B) for generic sources.
**Status:** ❌ **NOT FIXED**

**Fix Required:** Unify into a single browser pool that applies stealth, session persistence, and proxy rotation to ALL requests.

---

### 2.2 Stealth Script is Outdated
**File:** workers/scrapers/_browser_session.py
**Status:** ❌ **NOT FIXED** — Still uses hand-rolled `_STEALTH_SCRIPT` (~13 vectors from 2021)

**Missing evasion:**
- `navigator.userAgentData` (brands, platform, mobile)
- PerformanceEntry timing normalization
- Function.prototype.toString patch for Playwright-injected functions
- Audio context fingerprinting
- Font list fingerprinting
- Request header interception (Sec-CH-UA still leaks "HeadlessChrome")

**Fix Required:** Replace hand-rolled script with `playwright-extra` + `stealth-plugin` + `recaptcha-plugin`. See Fix Guide Phase 4.

---

### 2.3 No CAPTCHA Solving

**Sites that will block you:**

- Zillow — DataDome (invisible challenge)

**Fix Required:** Create `workers/captcha_solver.py` with 2Captcha/Anti-Captcha integration. Budget ~$2-5 per 1,000 solves. See Fix Guide Phase 3.

---

### 2.4 No Structured DOM Parsing
**Status:** ❌ **NOT FIXED** — All extraction still uses `BeautifulSoup.get_text() -> LLM`

**Fix Required:** For each implemented source, write:

- Playwright locators for SPA data (React/Vue/Angular apps)
- PDF table extraction with `camelot-py` or `tabula-py`
- Scanned PDF OCR with `pytesseract` or `paddleocr`

## 10. Conclusion

This codebase has **excellent infrastructure** (job queues, retry logic, browser pools, circuit breakers, Fargate deployment) but **the data extraction layer remains broken** (LLM hallucination, no form interaction, no CAPTCHA solving, no schema validation, no per-county scrapers).

**Do not try to fix 200+ sources at once.** Pick 10 high-value counties, write real Playwright scripts for each, add CAPTCHA solving, validate results with Pydantic, and build from there.

**The LLM-based extraction approach must die.** It is the single biggest reason you get empty results. The `_chat()` helper should be retained ONLY for post-extraction classification tasks (buyer type tagging), never for data extraction from raw HTML.

**Immediate next steps:**
1. Remove the 4 LLM extraction functions from `llm.py`.
2. Create `workers/scrapers/counties/` with 10 county scrapers.
3. Create `workers/models.py` with Pydantic schemas.
4. Replace `distressed.py` generic pipeline with county-specific dispatch.
5. Add `workers/captcha_solver.py` for RealForeclose and other protected sites.
